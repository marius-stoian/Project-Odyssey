# D-63 US-202 design decisions (hand edits on top of the seed)

Status: **Decided by Dominus (delegated)**, 2026-10-09, under D-41. The owner may override any line later; if one changes, US-202 is reopened. Design: docs/plans/M12-world-editing-design.md sections 3, 6 and 7.

| Q | Question | Options considered (recommended first) | Decision and reason |
|---|---|---|---|
| Q1 | How the world file meets the game | The file and the Region view only; the game also reads it at once | **The Region view and the sim loader (`sim::loadWorld`, `makeWorldRegion`) only.** The Codex puts "Play the edited region" in US-207, with the debugger; until then the game builds its land as before. |
| Q2 | Name and place of the file | `assets/worlds/<name>.json`, the view uses `default` and applies it only to the seed the file names | **As written.** A file for another seed is not applied and never overwritten (the tile coordinates belong to one seed's land). Choosing a name arrives with Play here (US-207). |
| Q3 | What a painted tile costs in the file | Only tiles whose biome differs from the seed's, per chunk, chunk-local coordinates, in tile order | **As listed.** Painting the seed's own biome removes the edit, so the file never holds a no-op. The price: if the settings change later so that the seed's land there changes, that tile follows the seed (the conflict list names the things that stood on it). |
| Q4 | What a painted tile does to what grows | The chunks within one tile are made again from the new land; resources stay as they were | **Made again.** A tree on a tile that is meadow now would be a lie; berries at the edge of a forest depend on the neighbours. A harvest in such a chunk is forgotten (edits are made before the land is played). |
| Q5 | Tools | Brush (round, 1 to 9), Rectangle, Fill, Reset (gives tiles back to the seed), Pan; the middle or right button pans while a painting tool is chosen | **As listed.** Fill is refused above 20,000 tiles and does not cross or paint the edge wall. |
| Q6 | Undo | One world history of 500 steps for all tools (D-61 Q5); a stroke, a rectangle and a fill are one step each; Ctrl+Z and Ctrl+Y inside the Region view | **As listed.** Undo and Redo only touch tiles, never the generator settings. |
| Q7 | Size cap | `kMaxWorldEntries` = 20,000 edits in all (D-61 Q6) | **A constant in `sim/world_file.h` for now.** It moves to Game Rules when Game Rules reaches the world. A brush stops at the cap and says so. |
| Q8 | Release of textures | Add `Renderer::destroyTexture` through Window and both backends (the GPU backend lets go at the start of the next frame); keep every picture ever made | **Added.** Repainting makes a picture again; the old one must go back. The overview and the Preview maps reuse one `Minimap` each, so they give theirs back too. |
| Q9 | Chunk pictures after a paint | Make the changed chunk's pictures again at once; draw the old picture until there is room (4 pictures a frame) for the new one | **Old picture until the new one is ready.** No flicker, same frame budget as US-200. |
| Q10 | Conflicts from regeneration | Resolve per conflict (keep, move, remove) in US-202; keep the list from US-201 | **Keep the list.** The acceptance of US-202 is painting, small files and Undo. Painted tiles now count in the conflict finder through `effectiveBiome`; per-conflict choices come with the placed things (US-204, US-205). |
