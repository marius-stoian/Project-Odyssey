# D-61 M12 design decisions (K-M12)

Status: **Decided by Dominus (delegated)**, 2026-10-09, under D-41 (the owner delegates the design questions of M10-M14 to Dominus). The owner may override any line later; if one changes, the story that built it is reopened. Design document: docs/plans/M12-world-editing-design.md.

| Q | Question | Options considered (recommended first) | Decision and reason |
|---|---|---|---|
| Q1 | Where the edits live | A world file `assets/worlds/<name>.json` holding only differences from the seed (brief 4.6); edit `region.json` and the run save; one big level file | **World file of differences.** Small readable diffs, regeneration can keep them (ADR-010, ADR-020), the run save stays small. |
| Q2 | How tile overrides are stored | Per chunk run lists with chunk-local coordinates, sorted; one flat list of tiles; a bitmap per chunk | **Per chunk, sorted lists.** Matches the chunk streaming; stable diffs; absent chunk = untouched. |
| Q3 | What regeneration does to edits | Overrides stay at their tile and a conflict list is shown, the owner decides each (keep, move to nearest valid, remove); overrides follow the land; overrides are dropped | **Stay and list conflicts, never change silently.** Nothing the owner placed is moved or lost without a click. A changed seed asks first. |
| Q4 | How the live preview is made | Call `Region::biomeAt` (pure) for a 1 pixel a tile minimap in 32-row slices; copy the generator into the Editor; render the full chunks | **Call `Region`.** One generator, no drift ("Same world"). |
| Q5 | Undo in the World tool | One world history for all M12 tools, up to 500 commands; join the Level `History`; one history per tool | **One world history.** Same reasoning as D-60 Q6: a world edit is not a Level command. |
| Q6 | Size cap on the world file | A Game Rules cap (default 20,000 entries); no cap; fixed cap | **Game Rules cap.** Keeps the file and the load time bounded; the owner can raise it. |
| Q7 | Reload while playing | Applies on the next Play here; hot reload of the world during play; restart the run on save | **Next Play here.** Moving land under a running clan breaks the simulation; the Editor's other data keep their hot reload (M11). |
| Q8 | What the run save records about the world | File name plus a content hash, warn on a changed hash and load the saved overrides; embed the whole world; name only | **Name and hash.** A run keeps the world it began in. A changed file is a warning, not a refusal. |
| Q9 | Region size and chunk size | Read-only in the Editor; editable with migration; editable without | **Read-only.** A different size moves every chunk key and breaks saves (`region_save` already refuses a mismatch). |
| Q10 | Unreachable places after a water or mountain edit | Warning list, never a block; block the edit; auto-repair | **Warning list.** The owner may want an island. |
| Q11 | Where the people overrides are created | The NPC population creates them at load with stable ids from the world file; a second people system in the world code | **NPC population.** No second people format (kSaveVersion 3 keeps its own state). |
| Q12 | Gate check of K-M12 step 1 | M11 done (`docs/gates/M11.md`, tag m11-done), D-40 and D-41 Decided | **Proceed.** The owner's M10b walkthrough answer and M11 manual checks are open but block nothing in M12. |
