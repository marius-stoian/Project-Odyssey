# D-62 US-201 design decisions (generator settings with live preview)

Status: **Decided by Dominus (delegated)**, 2026-10-09, under D-41. The owner may override any line later; if one changes, US-201 is reopened. Design: docs/plans/M12-world-editing-design.md section 5 (amended by this record).

| Q | Question | Options considered (recommended first) | Decision and reason |
|---|---|---|---|
| Q1 | Where Apply writes | `assets/data/sim/region.json`, patching only the changed lines; a `generator` section of the world file (D-61 Q1); both | **region.json.** The story's acceptance says "region.json use the new settings". The world file does not exist before US-202; when it does, per-world differences can be added without changing this. |
| Q2 | Which settings the form shows | All of region.json except `size` and `chunkSize`; all of them; only the biome ones | **All except size and chunk size** (D-61 Q9: they move every chunk and break saves). 14 fields, each with the file's range, the schema's help text and the cross rules (mountain level at least 100 above the lake level, herd maximum at least the minimum) in one checker, `sim::regionConfigProblems`, which a test keeps equal to `loadRegionConfig`. |
| Q3 | The seed | A Seed field with Roll; leave the seed to the game | **Leave it out of US-201.** The seed is not a setting of region.json; the run's seed comes with a new game, and changing it under a run in play has its own conflicts. The Region view shows the seed of the game in play. Design section 5 amended. |
| Q4 | What Preview draws | A 128 x 128 sample of the land the draft would make, painted 32 rows a tick (4 ticks), beside the same sample of the land on screen, with the share of water, mountain and forest of each; the full-size map; chunk pictures | **Low-resolution sample beside the old one.** It is the Codex's "low-resolution map off the main world" and appears in 0.2 s. It calls the same `sim::Region`, so it is the land Apply makes. |
| Q5 | What Apply does to the run in play | Only writes the file and reopens the Region view; also rebuilds the level in play | **Writes the file and reopens the Region view.** The land of a run in play is part of its save; the new settings are the next new game's land. |
| Q6 | The model of hand edits | Define `sim::RegionEdits` now (tile edits, placed things, people, places, camps, resources, tombstones) and the conflict finder; wait for US-202 | **Define it now**, small and without a file format (US-202 gives it one), so the "Keep edits" scenario is testable and US-202 to US-205 fill the same model. |
| Q7 | What counts as a conflict (design section 7) | Added entry on water, mountain or outside the region; a camp that fails the site check (unless forced); a tombstone with nothing left to take away; painted tiles are never conflicts | **As listed.** The camp check ignores tile paint (it uses the new land only) until US-202 puts the paint into the land. |
| Q8 | Who resolves conflicts | The owner, per conflict, in US-202; Apply resolves them | **The owner, in US-202.** US-201 never moves or drops an edit; it lists the conflicts in the panel (first two lines on screen, all in `conflicts()`). |
| Q9 | A draft that breaks a rule | Preview and Apply refuse and name the first problem; clamp silently | **Refuse and say which**, so a number is never changed behind the owner's back. |
