# D-68 US-207 design decisions (play the edited region)

Status: **Decided by Dominus (delegated)**, 2026-10-09, under D-41. The owner may override any line later; if one changes, US-207 is reopened. Design: docs/plans/M12-world-editing-design.md sections 11 and 12.

| Q | Question | Options considered (recommended first) | Decision and reason |
|---|---|---|---|
| Q1 | How New Game picks a world | A "World" row of buttons on the New Game screen; a typed name; only the command line | **A row of buttons: Generated, then one per file in `assets/worlds` (nine at most).** Picking a world replaces the seed field ("Seed: from the world file"): the land is the file's. `--world <name>` plays a file from the command line (with `--new-game` it picks the button). |
| Q2 | What Play here starts | The Editor's Play here on a hand-made level; a new run on the world | **A new run on the world file**, with a grown hero (the "Off" preset, Comfort Normal), no tutorial, standing on the chosen tile. The run is what makes the setup mean something: the store, debts, opinions and grudges of US-206 need a clan and a hero life. The **Play here** button of the Region view takes the middle of the view; **P** over the map takes the tile under the pointer. Water, mountain and the map's edge are refused with the reason. |
| Q3 | Unsaved edits | Play from memory; save first | **The world file is saved first** (when it has unsaved edits or does not exist yet), so the game plays exactly what the file says and the run can name it. A world made for another seed is never overwritten (as Save). |
| Q4 | What a test run saves | Autosave as any run; nothing | **Nothing.** Play here is a test of the edits; it must not overwrite the owner's real run. The autosave is skipped and no copy of the world is written. |
| Q5 | The way back | Esc only; Esc and F2 | **Esc and F2** return to the Editor with its own level and the Region view open on the same edits (the Editor's level is kept in memory while the world is played). |
| Q6 | What the run save records (D-61 Q8) | Name and hash only; also a copy | **Name and hash in `hero.json` (version 3: `world`, `worldHash`), and a copy of the file as it was in the save folder (`world.json`).** Name and hash alone can warn but cannot "keep the world the run began in"; the copy can. Loading a run whose file changed says so ("the world file ... was changed after this run began; the run keeps the world it began in") and plays the copy. A missing copy falls back to the file, with a note. A run on generated land removes an older copy. |
| Q7 | Old saves | Migration step; load as they are | **They load as they are.** `hero.json` versions 1 and 2 have no `world` fields (generated land); the region save keeps version 1 (its chunk changes are laid onto the world's land when `hero.json` names a world, onto the seed's land otherwise). A test loads a version 2 and a version 1 save. |
| Q8 | Where the setup is applied | Once at the start of the run; every time the game is built | **The clan's and the hero's setup once, at the start of the run** (they are then in `clan.json` and `hero.json`); **the rivals' every time they are made** (they are made again from the seed on every load, so their meals must be set again). The rival camps the owner placed go to `Rivals` at the same time. |
| Q9 | The Quick check on the world | Include it; leave it out | **Left out.** The Quick check runs a clan on a seed from the data folder (US-194); running it on a world needs the check to take a world file. It is not in the acceptance criteria of US-207; a new story if wanted. |
