# US-180 Quest data and runtime: plan and checks

Design: docs/plans/M10-quests-design.md sections 2-3. Guide: docs/guides/quests.md. Decisions: D-57.

## Built
- `src/sim/quest_data.{h,cpp}`: the quest types, `parseQuest` (errors as `file:line: message`), `parseObjective`, `writeQuest`, `loadQuests`.
- `src/sim/quest_book.{h,cpp}`: `QuestBook` (locked, available, active, done, failed; steps, branches, hints, fail rules, rewards through `ActionRunner::runEffects`), the events queue, save and load, hash.
- Rule language: functions `quest(id)` and `step(id)`, effect verb `quest start|complete|fail <id>` (known to the parser; the game runs the verb in US-182).
- Game: `OdysseyGame::quests()` loads `assets/data/quests/` with the other data (and on F5), calls `tickQuests` every 10 ticks, saves in `things.json` version 2 (version 1 still loads).
- Flat in `src/sim/` (the Codex said `src/sim/quests/`; every other Simulation file is flat and `boundary.h` is found beside it).
- Schema `assets/data/schemas/quest.schema.json` (the format of brief 4.3; the validator arrives in M11).
- No quest ships yet: `first-day` arrives with US-185.

## Manual checks (run at X-M10)
1. Put the guide's `first-day.json` into `assets/data/quests/`, start the game: the log says `Quests: 1 loaded from 1 file(s), 0 error(s)` and `Quest first-day: ...`.
2. Break the file (a `next` that names no step): the log and the F5 panel say `quests/first-day.json:<line>: unknown step "..."`; fix it, press F5, the quest loads.
3. Save and load the game: the quest is on the same step with the same progress.
