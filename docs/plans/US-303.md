# US-303 Live reload of every data file: plan and checks

Design: docs/plans/M10b-editor-help-design.md section 5. Decisions: D-58 Q4, Q8, Q9; D-59 Q3 (toast plus status). NFR-09: a set reloads in under 100 ms.

## Built
- `DataReload` (src/game/data_reload.*): the registry. A `DataSet` has a name, the files or folders it watches, an all-or-nothing `reload` and a `restartOnly` flag. `changed(file)` reloads each set that watches the file once (a live set takes the file before a restart-only set that only matches its folder), `reload(name)`, `reloadAll()` (F5, restart-only sets left out), `last(name)`. The registry measures each reload.
- `OdysseyGame` (src/game/odyssey_reload.cpp) registers five live sets and one restart-only set:
  - `interactions` (interactions, dialogue, quests; the existing `reloadInteractions`, plus the partner defaults), `npc-classes` (the existing F5 block, now behind the registry), `lights` (`lights.json`: read aside, refused when a catalog or the sun and moon still name a kind it drops; placed lights and objects look their kind up each frame, so they shine in the new colour at once), `catalog` (`plants.json`, `objects.json`, `characters.json`), `help` (`editor/help.json`, `EditorHelp::reload`).
  - `catalog`: `loadDefinitions` and `loadCatalogs` read whole into a copy; only a clean copy is taken. The plant catalog is swapped and every `WorldPlant::def` is pointed at the new entry **by kind name** (CI-007), `defaultBodies_` rebuilt, obstacles of blocking plants updated, plants that came (back) into the catalog stand in the world, the object page and plant art rebuilt, the Definitions names (plants, objects, characters) replaced, the palettes rebuilt (`Editor::dataChanged`).
  - `next-start`: weapons, animals, effects, weather, tiles, materials, buildings, hero data, sim, sky, celestial events, story events. A save only says "`<file>` applies at the next start" and nothing is half-applied.
- Missing kind: `findMissingKinds` lists the placed plants, lights and characters whose kind is gone; each gets a warning naming the level entry, play skips it (as before) and a red "?" (`drawMissingMarker`) stands where it was placed, in the Editor and in play.
- What the owner sees: a two-second toast (red on failure), and the mistakes panel of every set (`Data files: N mistake(s)...`) until the files are fixed. Editor saves of the graph editors read the `interactions` set through the registry; F5 reads `reloadAll`.
- Docs: "Live data" in docs/guides/editor.md; the "restart the game" lines of the guides are gone or say exactly which files apply at the next start.

## Technical choices (changes to the design document)
- **Weapons, animals, effects, weather, tiles, materials, buildings kinds, hero data (items), sim data are not swapped live** (CI-021). The play state holds them by raw pointer, by index (tile numbers) or in long-lived structures (`WorldWeapon`, `ArcShot`, `Projectile`, `Enemy`, the hero's life, the building layer). Swapping them needs a story of its own per catalog; until then the set `next-start` reports the change and never half-applies it. The Codex prompt lists characters, plants, objects, lights and the help as the files that matter for the acceptance criteria; those are live.
- A placed character whose kind changed keeps the values it has in the level; the play state of enemies is rebuilt from the level at F1 (the Editor reads the new kinds at once).
- The registry is game-agnostic (no game types in `data_reload.h`); the sets are the game's.

## Tests (tests/game/data_reload_test.cpp, "US-303 ...")
Registry (watch rules, once per set, restart-only), Catalog (a light's colour; a new light kind in the Editor's names), Object (added to objects.json: catalog and palette names), Follow (a placed plant takes the new values, keeps its id, points into the new catalog), All or nothing (a broken interaction keeps the old data and names file and line; broken lights.json and objects.json change nothing), Missing kind (plant: marker, warning, skipped, comes back) and Missing light, Next start (weather.json), Help (clean taken, broken ignored), Timing (every set under budget; the numbers go to docs/evidence/US-303/), Screen (the red marker is drawn). Determinism: the hash test runs unchanged, no reload happens in it (the watcher of US-304 is off in tests).

## Manual checks (docs/evidence/US-303/)
1. `timings-debug.txt` and `timings-release.txt`: every set under 100 ms in Release (NFR-09; Debug with AddressSanitizer is slower and checked against 1 s).
2. `missing-marker.png`: the red "?" where a placed wheat plant stood after wheat was deleted from plants.json.
3. In the running game: change a light colour in lights.json, press F5: placed lights change colour; add an object to objects.json, press F5: it is on the last page of the Plant palette.
