# US-301 Suggestion list widget: plan and checks

Design: docs/plans/M10b-editor-help-design.md section 3. Decisions: D-58 Q3; D-59 Q2 (the list opens on focus).

## Built (Luna Engine only, src/luna/engine/ui.* and input.*)
- `SuggestList`: values, filter (prefix matches first, then substring, any letter case, no duplicates), at most 8 rows, highlight and scrolling, draw under the field or above it where it would leave the screen (`UiPainter::screen()`), marks `^` and `v` for hidden rows.
- `TextField` and `NumberField` get `suggest` (typed text to a list of strings). `TextField::listItems` completes the item after the last comma and keeps the ones before it. No game field sets `suggest` yet (US-302).
- Keys: `UiInput` gains `up`, `down`, `tab`, `escape`, fed by four new intents `ListUp`, `ListDown`, `ListTab`, `ListEscape` that only the arrow keys, Tab and Escape raise (W, S, Shift and the rest are not arrows, so a typed letter never moves the highlight). The old intents (`MoveUp`, `SwitchWeapon`, `OpenMenu`) still fire as before.
- Behaviour: focus opens the list with every value; typing filters; Down/Up move; Tab accepts the highlighted row; **Enter accepts only after Up or Down** (otherwise it commits the typed text, as before); Escape closes the list, keeps the text and keeps the field focused; typing again reopens it; a click on a row accepts it; a click elsewhere commits the text as before. Accepting writes the row into the field and commits it (`onChange`). A closed list or a field with no `suggest` uses no input at all.

## Technical choices (changes to the design document)
- Enter rule: the design said "Enter accepts the highlighted row"; the first row is highlighted from the start (so Down then Tab gives the second row, as the acceptance scenario says), which would make Enter replace text typed from scratch. Enter therefore accepts only after the owner moved the highlight.
- New intents instead of reusing `MoveUp`/`MoveDown`: those are also W and S, and a letter typed in a focused field must not move the highlight.

## Tests (tests/luna/ui_test.cpp, "US-301 ...")
Filter, Keys (Down then Tab; Escape keeps the text; Down, Down, Up, Enter), Enter without a pick, Quiet (a field with no list, an unfocused field, the list closed), Rows (8 at a time, scrolling, last row), Placement (below and above), Click (a row; elsewhere), List items (comma lists), Numbers, Intents (arrows still move).
