# US-304 File watch for outside edits: plan and checks

Design: docs/plans/M10b-editor-help-design.md section 6. Decisions: D-58 Q8 (auto on save plus a file watch, live within 1 s).

## Built
- `FileWatcher` (src/game/data_reload.*): polls with `std::filesystem` (no thread, no library). The caller gives it the time in seconds (a test drives it with a clock of its own). It looks at the watched roots one after the other, spread over 0.25 s (a tick pays for a few roots, not for all), compares time and size per file, and holds a change until the file has been quiet for 0.3 s (a double write counts once). Appeared and removed files count. Hidden, `~`, `.tmp`, `.swp`, `.bak`, `.bak1..3` names are ignored. `noteOwnWrite(file)` ignores the one change an own write made; `resync(root)` takes the times of a root as they are after the game read it itself and drops what waited there.
- `DataReload::changed(files)`: several settled files reload each set once.
- `OdysseyGame`: `setWatching(true)` registers every root of the sets plus the open level file and snapshots; `update` calls `pollFiles` with a steady clock; `pollFiles(now)` reloads the sets and shows the toast. Off by default for the class (tests, headless); `apps/odysseus/main.cpp` turns it on unless `--no-watch`.
- Own writes: the graph editors' Save read the set themselves (`ownReload`: reload, then `resync` the set's roots); the Editor tells the game after it writes the level and after the class book writes a class or kind file (`noteOwnWrite`); story-event and prefab saves `resync` their folder.
- The open level: `Editor::levelChangedOnDisk()` reads it again when nothing is unsaved (the view stays), else keeps everything and the status line and a red toast say the file changed on disk. While the game plays the reload waits and is done when the Editor opens.
- Docs: "Files saved outside the game" and `--no-watch` in docs/guides/editor.md; the guides and lesson 18 say saves reload by themselves.

## Technical choices (changes to the design document)
- Poll slicing: the design said "poll every 250 ms". A full pass over about 200 files costs milliseconds in a Debug build, so the roots are looked at in slices through the 0.25 s (still every file four times a second) to keep every tick cheap (budget 0.5 ms a frame, measured in the test).
- The class is off by default and `main` turns it on: a game object made by a test never reloads by itself, so a determinism test cannot see a reload. `--no-watch` is for a person who wants it off in the real game.
- The file stamp is time plus size, not a hash: cheap, and an edit that keeps both equal in the same second is vanishingly rare for text files.

## Tests (tests/game/data_watch_test.cpp, "US-304 ...")
Watcher (changed, double write once, removed and new files, temporary files ignored), Polls (at most four looks a second), Own writes (ignored once, a later outside change is not, resync), Outside (an interaction file is live within a second, a broken one keeps the old data), several files reload each set once, Editor saves are not read a second time (a graph save and the level save), Open level (unsaved: nothing overwritten and the status line says so; clean: read again), Off (no polling by itself; F5 works), Cost (per tick on the shipped data).

## Manual checks (docs/evidence/US-304/)
1. `watch-cost-release.txt`: average and worst cost of a tick in Release (budget 0.5 ms).
2. Run the game, open an interaction file in a text editor, change a number and save: a toast says "Reloaded interactions" within a second. Break the file: a red panel names the line.
